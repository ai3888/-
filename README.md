# GitHub 项目雷达

每天自动在 GitHub 上找「有潜力」和「值得关注」的开源项目，结果写在 [`reports/latest.md`](reports/latest.md)，历史报告按日期存在 `reports/` 里。

## 判断标准

先用代码按客观数据打分（满 100 分），再让 GPT 看入选的项目做最后判断。

| 维度 | 权重 | 看什么 |
|---|---|---|
| 涨星速度 | 40 | 最近每天涨多少星：每天记一次星数，和前几天比；第一次见到的项目先按总星数 ÷ 天数估算 |
| 开发活跃度 | 20 | 近 30 天提交数、最近一周有没有更新 |
| 社区 | 20 | 贡献者人数、fork 数占星数的比例（有人真的在用、在改） |
| 规范度 | 20 | 有没有许可证、topics、主页、正式发版 |

- **🚀 潜力股**：创建不超过 90 天，分数 ≥ 55
- **👀 值得关注**：不限创建时间，分数 ≥ 65
- **直接排除**：fork 来的、已归档的、没有简介的、30 天没更新的、awesome 列表、教程、面试题
- **风险提示（每条扣 10 分）**：星很多但几乎没人 fork（可能刷星）；只有一个人维护且近 30 天几乎没提交
- **GPT 复核**：看 README 判断是不是真有新意、是不是套壳或营销、和你关注的方向是否相关，给出「推荐 / 一般 / 跳过」
- **不重复推荐**：推荐过的项目 14 天内不再出现

这些数值都能在 [`config.toml`](config.toml) 里改。

## 为什么这样分工能省 token

搜索、过滤和打分都由代码完成，不花 token。每天只有最后入选的十几个项目，以精简数据加每个约 1500 字 README 的形式，一次性交给 GPT。每次大约几千 token，用量会写在报告底部。

## 开始使用

1. **（可选）配置 GPT**：仓库 Settings → Secrets and variables → Actions：
   - Secrets 里添加 `OPENAI_API_KEY`
   - Variables 里可以添加 `OPENAI_MODEL`（模型名，默认 `gpt-4o-mini`）和 `OPENAI_BASE_URL`（使用中转服务时填写，例如 `https://xxx.com/v1`）
   - 不配置也能运行，只是没有 GPT 点评
2. **手动跑一次试试**：Actions → 项目雷达 → Run workflow。跑完后仓库里会多出 `reports/` 目录。
3. **之后每天北京时间 6 点多自动运行**（和 AI 日报素材一起）。想在手机上收到提醒，就把 `config.toml` 里的 `create_issue` 改成 `true`，每次运行都会开一个 issue，GitHub App 和邮件会通知你。

如果第 2 步提交报告时报 403，到 Settings → Actions → General → Workflow permissions 选择「Read and write permissions」。

## 调整标准

都在 `config.toml` 里：

- `interests`：你关注的方向，GPT 按它判断相关度
- `[[queries]]`：去哪里找，写法和 GitHub 搜索框一样，比如 `language:rust topic:cli stars:>200`
- `[filters]`：排除哪些项目
- `[weights]` / `[full_marks]`：各维度的权重和满分标准
- `[tiers]`：分数线、每次最多推荐几个、冷却天数

刚开始可以先跑几天看看报告。推荐太多就提高分数线，太少就降低分数线或者加搜索条件。

## 和你现有的 GPT 配合

每天的筛选交给这里。你的 GPT 只需要读一个文件：

```
GET https://api.github.com/repos/<你的用户名>/<仓库名>/contents/reports/latest.md
Accept: application/vnd.github.raw
```

然后对感兴趣的项目再深入问，比如「第 2 个项目和 XX 比怎么样」。这样 token 花在你真正关心的项目上。

## 只用 GPT 的做法

不想跑脚本的话，可以让 GPT 自己定时执行：[`gpt-task.md`](gpt-task.md) 是写给 GPT 的完整任务说明，包括方向、步骤、判断标准和输出格式。先填好其中的「我的方向」，再让 GPT 每次运行时读取这个文件。

## AI 日报（每天早上 8 点）

1. 每天北京时间 6:37，GitHub 自动运行「每日 AI 雷达」：先跑上面的项目雷达，再从 [`ai_news.toml`](ai_news.toml) 里的来源（HF 每日论文、Hacker News、OpenRouter、OpenAI/Google/Anthropic/Meta 等官方博客、Newsletter、科技媒体、量子位、油管频道）抓取最新内容，用代码去重、算热度，生成日报素材 [`reports/ai-news/latest.md`](reports/ai-news/latest.md)，每天的存档在 `reports/ai-news/` 里
2. 素材分三块：大家都在讨论的（同一件事在几个不同来源出现）、新东西（官方发布、新模型、开源项目和 Skill、Show HN 新工具）、论文（按 HF 点赞数排序）
3. 素材最前面是给 GPT 的写作说明，来自 [`ai_news_guide.md`](ai_news_guide.md)。想改日报的标准或格式，改这个文件就行
4. 早上 8 点，ChatGPT 的定时任务读素材、写日报推送给你

流程里不调用任何付费模型：抓取和排序由代码完成，挑选和写日报交给 ChatGPT 里的 GPT。

其他：

- 改了来源后，GitHub 会自动跑一次「AI 资讯雷达 · 接入检查」，在运行页面的 Summary 里列出每个来源能不能用
- 可选：仓库 Secrets 里加 `GEMINI_API_KEY`，接入检查会顺便测试 Gemini 能不能看油管视频（目前部分 Google 账号的项目会被拒绝访问）

## 每周素材包（写抖音长文用）

把这一周跟 AI 的对话记录、随手记和代码提交整理好，交给 Claude 或 ChatGPT。AI 分两轮处理：第一轮整理事实、设计故事、提几个确认问题；你回答之后，第二轮只用确认过的事实写初稿。不用再自己翻记录、自己概括。

聊天记录都在你自己电脑上，所以这个要在自己电脑上跑。`weekly/` 文件夹不会提交到 GitHub。

AI 要用四样材料：

| 材料 | 来自哪个文件 | 作用 | 放在哪 |
|---|---|---|---|
| 写作说明 | [`weekly_guide.md`](weekly_guide.md) | 两轮流程、事实规则、怎么讲成故事 | 项目说明 |
| 风格材料 | [`weekly_style.md`](weekly_style.md) | 从旧文整理的写法，只学结构、节奏和用词，不提供本周经历 | 项目文件 |
| 连载档案 | `weekly/连载档案.md` | 主角卡、没解决的问题、留意过的细节，决定开头接什么、结尾留什么 | 项目文件，每篇定稿后换新版 |
| 本周素材 | 程序整理 | 这几天的 AI 对话、随手记、代码提交、截图列表 | 每周新对话里上传 |

前三样装进 Claude 或 ChatGPT 的「项目」，项目就是你固定的写作窗口；每周在项目里开一个新对话，只上传本周素材。不要一个对话用到底：对话越长，AI 越容易漏看前面的规则，上周的事也会混进这周。

**第一次用**

1. 准备聊天记录，用了哪个就弄哪个：

   | 用的 AI | 怎么拿到记录 |
   |---|---|
   | ChatGPT、Claude（网页版或 App） | 网页版设置里的「导出数据」，邮件里的 zip 下载下来放进 `weekly/inbox/` |
   | Claude Code、Codex（装在这台电脑上的） | 不用管，自动读取这台电脑上的记录 |
   | 网页版 Claude Code | 记录在云端，不在你电脑上，程序读不到；需要的话把相关对话复制到 txt，放进 `weekly/inbox/` |
   | DeepSeek | 设置里如果有导出数据，同上。导出格式还没用真实文件验证过，读不出来时会提示 |
   | 豆包、Kimi、Trae 等 | 目前没找到可靠的官方导出，把聊天内容复制到 txt 文件里，放进 `weekly/inbox/` |
   | 截图 | 放进 `weekly/inbox/`，素材里会列出文件名和时间；想让 AI 看图，就和素材文件一起上传 |

   导出的是全部历史，程序只取这几天的。每周放一份新的就行，旧的留着也没关系，同一个对话会自动去重。放进去的 json 认不出来时，会打印「[认不出]」和它有哪些字段（不打印内容），把这一行发给 Claude 就能加上支持。

2. 生成项目文件：

   ```bash
   python3 weekly.py kit
   ```

   第一次运行会新建 `weekly/连载档案.md`。打开把【待填】和「待确认」改成真实情况，再运行一次 `kit`。`weekly/项目文件/` 里会有三个文件：`写作说明.md`、`风格材料.md`、`连载档案.md`，另外还有一个三样合在一起的 `写作手册.md`，想整份交给 AI 时用它。

3. 在 Claude 或 ChatGPT 里新建一个项目，比如叫「抖音长文」：
   - 把 `写作说明.md` 的全文贴进项目说明（项目的 instructions）。如果太长放不下，就把它也作为文件上传，项目说明里只写一句「每次对话都先读完写作说明.md，严格按它执行」
   - 把 `风格材料.md` 和 `连载档案.md` 上传成项目文件

4. 想到什么随手记一句。聊天记录只能看出你做了什么，看不出你当时的感受和最后的结果：

   ```bash
   python3 weekly.py note "部署又挂了，搞到两点，差点放弃"
   ```

**每周**

```bash
python3 weekly.py              # 最近 7 天，写到 weekly/out/本周素材-日期.md
python3 weekly.py --days 14    # 最近 14 天
```

1. 在项目里开一个新对话，上传 `本周素材-日期.md`，说一句「开始第一轮」。发之前可以扫一眼，有不想给 AI 看的对话就删掉那一段
2. AI 给出事实清单、选题和最多 3 个确认问题。一句话回答就行，比如「1 选 B，2 对，3 不对，是因为……，选题用 2」
3. AI 写初稿，后面附三五行连载档案更新。正文和档案更新一起看，改到满意为止
4. 定稿后，把确认过的档案更新抄进 `weekly/连载档案.md`，运行 `python3 weekly.py kit`，再把项目里的 `连载档案.md` 换成新版。如果你说过某个改法「以后也这样」，就加进 `weekly_style.md` 最后一节，同样换掉项目里的 `风格材料.md`

不想建项目的话，用 `python3 weekly.py --bundle`，四样材料会打成一个文件 `weekly/out/素材包-日期.md`，直接拖进对话框，说「按开头的写作说明，先做第一轮」。

**最重要的一条：分清 AI 建议的和你真正做了的**

聊天记录里大部分是 AI 说的话。AI 给了方案不代表你照做了，生成了代码不代表产品跑通了。所以：

- 程序给每段记录标清楚能证明什么：网页聊天里 AI 只能给建议；Claude Code / Codex 会记下「AI 实际动手」改了哪些文件、运行了几次命令；代码提交说明改动真的存进了项目。但这些都不等于做成了
- 依据要对准具体结论：部署记录只能说明这个版本部署了，不能说明某个功能通过了。来源互相矛盾时，AI 要先问你
- 原因、预期和感受，记录里有原话就直接用；没有的话，AI 先说出它的理解，你回答「对」或「不对，是因为……」。没确认的不进正文

**程序帮你做了什么**

- 只留这几天的消息。ChatGPT 里改过问题、重新生成的，只留最后那一版；调用工具的过程和思考过程都去掉
- 你的消息比 AI 的回答重要：AI 的回答只留开头，代码块换成「〔代码 N 行〕」，你贴的报错只留关键的一行
- 按你说的话打标记，让 AI 重点看：⚠️ 可能卡住了、❓ 最后还在说有问题、✅ 提到做成了、🔀 可能改主意了、⏱ 聊了很久。标记是按关键词打的，AI 会再看原话判断
- 统计每天聊了多少、提交了多少次代码；Claude Code / Codex 在哪个项目里干过活，就顺便读那个项目这几天的提交记录
- 素材太长就自动压缩到 `max_chars` 以内（默认 4 万字）：先缩短 AI 的回答，再缩短你的消息，最后把小对话折叠成一行

想改压缩到多少字、「卡住」的关键词、多加几个项目文件夹，改 [`weekly.toml`](weekly.toml)。想改 AI 的流程和规则，改 [`weekly_guide.md`](weekly_guide.md)；想改写法，改 [`weekly_style.md`](weekly_style.md)。改完运行 `python3 weekly.py kit`，把项目里对应的文件换成新版。

## 在自己电脑上运行

需要 Python 3.11 或更高版本，不用安装任何依赖（Windows 上把命令里的 `python3` 换成 `python`）：

```bash
export GITHUB_TOKEN=你的GitHub令牌     # 不设置也能跑，但 GitHub 限流很严
export OPENAI_API_KEY=sk-...           # 可选
python3 scout.py --dry-run             # 只打印报告，不写文件
```

AI 日报素材：

```bash
export GEMINI_API_KEY=...              # 可选
python3 ai_news.py --check             # 检查每个来源，不写文件
python3 ai_news.py --dry-run           # 只打印今天的素材，不写文件
python3 ai_news.py                     # 生成 reports/ai-news/日期.md 和 latest.md
```
